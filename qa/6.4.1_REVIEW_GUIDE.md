# EMS 6.4.1 Strict Review Guide

Base release: EMS 6.4 targeted hardening, based on main commit
`cb15919032596021e732321a4c7c84e60429f5f6`.

## Implemented in 6.4.1

- Removed all database DDL and schema mutation from `backend/main.py`.
- Added Alembic configuration and an idempotent industrial schema adoption revision.
- Deployment runs `alembic upgrade head` before FastAPI starts.
- Preserved legacy wing/slot naming adoption inside the versioned migration.
- Enforced strict command FSM; queued commands cannot jump directly to executing.
- Preserved 120-second delivery lease and 300-second absolute command expiry.
- Enforced terminal `COMPLETED/FAILED/EXPIRED -> ACKED` lifecycle.
- Kept Pi API credentials canonical in HTTP headers.
- Prevented retired devices from being reassigned through society configuration.
- Clamped dashboard feedback visibility to installed device feedback capability.
- Pi refuses hardware mutation if durable `EXECUTING` state cannot be persisted.
- Kept low-level GPIO/storage/resource subsystem hashes locked.

## Mandatory qualification still outstanding

These cannot honestly be marked software-resolved:

1. Physical HIL: welded contactor, missing feedback, power loss during 500 ms interlock.
2. Storage endurance: 7-30 day soak on the exact production USB/storage device and OS;
   measure application writes, total filesystem/block writes, system WAF and latency.
3. Web auth: migrate JWT from localStorage to HttpOnly/Secure/SameSite cookies with
   short-lived access tokens and refresh rotation.
4. Secure OTA: Ed25519 signature verification, staged A/B update and automatic rollback.
5. CI: run backend/Pi regression tests and frontend build on every commit.
6. Production database deployment must be tested against a backup/restore procedure
   and a real Postgres instance before certification.

## Release rule

This candidate is a **strict hardened software candidate**, not a claim of industrial
certification or 10-year flash-life certification. Promote only after the mandatory
qualification gates above pass on the production hardware and deployment environment.
