# EMS SaaS 6.4.1 — QA Review Guide

Base main commit: `cb15919032596021e732321a4c7c84e60429f5f6`

## Release intent
Targeted industrial hardening without rewriting the proven GPIO/storage/resource subsystems.

## Mandatory offline checks
- Python compilation for backend and Pi firmware.
- Shell syntax check for Pi setup.
- Legacy STATE_VERSION=4 load compatibility.
- Legacy SQLite queue migration compatibility.
- Strict command FSM and ACK contract checks.
- Explicit storage-device provisioning checks.
- No destructive Pi-device/society lifecycle deletion.

## Mandatory pre-production qualification gates
1. Hardware-in-the-loop: welded contactor, missing feedback, power loss during the 500 ms interlock, restart/reconciliation.
2. Storage endurance soak on the exact production USB device and OS; measure application writes, total filesystem/block writes, NAND-equivalent workload, and system write amplification.
3. Versioned PostgreSQL migrations with Alembic; startup code must not perform uncontrolled schema evolution in production.
4. Secure OTA: signed artifacts, signature verification before staging, staged A/B update and automatic rollback.
5. Web session hardening: prefer Secure/HttpOnly/SameSite cookies over localStorage JWTs; add CSRF protection as appropriate.
6. Dependency/security scanning and full CI including a production Next.js build.
7. Production credential rotation and secret-management review.

## Important status
This ZIP fixes the Render startup DDL crash. It is a hardened candidate, not a production certification. The physical and deployment qualification gates above remain open until executed against the real target hardware/infrastructure.
