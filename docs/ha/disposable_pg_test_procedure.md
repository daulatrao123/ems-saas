# Disposable PostgreSQL test procedure (prepared, NOT executed)

Purpose: verify the publication inventory and the replication SQL against a real
PostgreSQL 16 server, using two disposable local clusters. Nothing here touches Neon,
Aiven, Render or production. Run this only after the PostgreSQL 16 runtime blocker is
resolved (see Phase 1 status).

## Preconditions

- A PostgreSQL 16 server binary with `initdb`, `pg_ctl` and `psql` that the OS allows
  to execute. Windows Application Control currently blocks `lib/dict_snowball.dll` in the
  EDB build, so this step is blocked until an administrator approves that path, or a
  PostgreSQL install is approved.
- Python 3.12 with `psycopg[binary]==3.3.9`, `alembic==1.13.3`, `SQLAlchemy==2.0.36`
  installed in an isolated virtualenv outside the repository.
- `wal_level=logical` on the **local publisher cluster only**. This is a local setting, not
  a Neon setting.

## Variables

    PGBIN=<path to PostgreSQL 16 bin>
    WORK=<temp dir outside the repo>           # e.g. %TEMP%\ems_pg_disposable
    PUB_PORT=55432                             # disposable publisher (plays Neon)
    SUB_PORT=55433                             # disposable subscriber (plays Aiven)
    PASS=<random, generated per run, never committed>

Use a random password per run. Do not write it to any tracked file.

## Step 1: Start two isolated clusters

    "$PGBIN/initdb" -D "$WORK/pub" -U ems_test --pwfile=<passfile> -E UTF8 --auth=scram-sha-256
    "$PGBIN/initdb" -D "$WORK/sub" -U ems_test --pwfile=<passfile> -E UTF8 --auth=scram-sha-256

Publisher config (append to `$WORK/pub/postgresql.conf`):

    listen_addresses = '127.0.0.1'
    port = 55432
    wal_level = logical
    max_replication_slots = 10
    max_wal_senders = 10

Subscriber config (`$WORK/sub/postgresql.conf`):

    listen_addresses = '127.0.0.1'
    port = 55433
    max_logical_replication_workers = 4

Start both, bounded:

    "$PGBIN/pg_ctl" -D "$WORK/pub" -l "$WORK/pub.log" -w -t 60 start
    "$PGBIN/pg_ctl" -D "$WORK/sub" -l "$WORK/sub.log" -w -t 60 start

Expected: both start within 60 seconds. Confirm with `psql -h 127.0.0.1 -p 55432 -U ems_test -c "SELECT version();"` showing PostgreSQL 16.x.

## Step 2: Apply the full migration chain to the publisher

Create two databases, `ems_pub` on 55432 and `ems_sub` on 55433.

    cd backend
    DATABASE_URL="postgresql+psycopg://ems_test:<PASS>@127.0.0.1:55432/ems_pub" \
      <venv>/python -m alembic upgrade head

Expected: exit 0, 19 revisions applied, head = 0019. Confirm the table count against
`docs/ha/publication_inventory.md` Section 1: 24 base tables, including `pi_commands_archive`.

Repeat on the subscriber with `ems_sub` on 55433, so both sides have identical schema.

## Step 3: Verify schema matches the inventory

    SELECT count(*) FROM information_schema.tables
     WHERE table_schema='public' AND table_type='BASE TABLE';    -- expect 24

    SELECT c.relname FROM pg_class c JOIN pg_namespace n ON n.oid=c.relnamespace
     WHERE n.nspname='public' AND c.relkind='r' AND NOT EXISTS (
       SELECT 1 FROM pg_constraint p WHERE p.conrelid=c.oid AND p.contype='p');
    -- expect 0 rows (every table has a primary key)

Record the actual counts. Any difference from the inventory is a finding, not a pass.

## Step 4: Create the publication on the publisher

Use the SQL generated by `backend/ha/replication.py::build_create_publication` with the
table list **excluding** the credential columns or tables, until the owner decides
(see inventory Section 3). Column lists require PostgreSQL 15+.

    -- example only; generate the real list from the builder
    CREATE PUBLICATION "ems_pub" FOR TABLE "societies", "users", ...;

Confirm: `SELECT pubname, puballtables FROM pg_publication;` shows `puballtables = f`.

## Step 5: Initial synchronisation and subscription on the subscriber

Copy the schema-only state by dumping the publisher schema, applying it to the subscriber
database before subscribing (DDL is not replicated). Then create the subscription with
`build_create_subscription_aiven` against local `127.0.0.1:55432`. Local equivalent of the
Aiven path uses `CREATE SUBSCRIPTION`, not `aiven_extras`, because the disposable
subscriber is not Aiven; record that substitution in the results.

Expected: `SELECT subname, subenabled FROM pg_subscription;` shows the subscription enabled.
Wait (bounded, 120 s) for `pg_stat_subscription` to show an apply worker.

## Step 6: Replication checks

1. Insert one row into `societies` on the publisher; confirm it appears on the subscriber
   within 30 seconds.
2. Update and delete a row; confirm both propagate.
3. Read lag with `build_slot_lag_query()` on the publisher. Expect `retained_bytes` small
   (under 1 MB) after the test writes settle.
4. Feed the lag value to `decide_lag(lag, warn_s=5, ceiling_s=30)`; expect `OK`.

## Step 7: Slot-loss and resync (destructive, disposable only)

1. Stop the subscriber cluster.
2. Drop the publisher slot (disposable only): `SELECT pg_drop_replication_slot('<slot>');`
3. Restart the subscriber. Expect the apply worker to fail with a missing slot.
4. Classify the observed state with `classify_slot_loss`; expect `LOST`.
5. Recreate the publication and subscription with a fresh slot. Confirm recovery.

Record the exact server error text. It is the evidence used to tune
`classify_slot_loss`.

## Step 8: Sequence check

Insert into `societies` on the publisher to advance its sequence. On the subscriber the
sequence does not advance. Confirm this, then apply `build_sequence_sync` on the subscriber
with the publisher's `last_value`. Expect the next subscriber insert to succeed with no
duplicate-key error. This demonstrates risk R4.

## Step 9: Routing tests against the local database

    DATABASE_URL=postgresql+psycopg://...@127.0.0.1:55432/ems_pub  (legacy mode)

Run the dedicated routing suite and confirm the legacy URL is used unchanged.

## Step 10: Teardown

    "$PGBIN/pg_ctl" -D "$WORK/sub" -m fast -w -t 60 stop
    "$PGBIN/pg_ctl" -D "$WORK/pub" -m fast -w -t 60 stop
    rm -rf "$WORK"

Confirm no `postgres` process remains (`tasklist | findstr postgres` on Windows).

## Pass criteria

- Both clusters start and accept connections.
- All 19 migrations apply cleanly on both sides.
- Table count is 24 and every table has a primary key.
- Initial sync and a live insert/update/delete propagate.
- Slot-loss is observed and classified as `LOST`.
- The sequence gap is observed and corrected by `setval`.
- Teardown leaves no processes or files.

Any step that cannot run is recorded as **not verified**, not as passed.
